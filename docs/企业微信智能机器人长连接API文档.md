\# 企业微信智能机器人长连接API文档 > 最后更新：2026/03/08 --- ## 一、概述 智能机器人支持WebSocket长连接模式，实现消息/事件回调接收、消息回复与主动推送能力。官方提供**Node.js SDK（aibot-node-sdk）** 可快速部署接入，长连接模式无需处理消息加解密，可复用连接实现低延迟交互。 ## 二、长连接与Webhook（短连接）能力对比 | 特性 | Webhook（短连接） | WebSocket（长连接） | | :--- | :--- | :--- | | 连接方式 | 每次回调新建连接 | 复用已建立长连接 | | 延迟 | 较高（每次建连） | 低（连接复用） | | 实时性 | 一般 | 好 | | 服务端要求 | 需公网可访问URL | 无需固定公网IP | | 加解密 | 需处理消息加解密 | 无需加解密 | | 复杂度 | 低 | 较高（需维护心跳） | | 可靠性 | 高（无状态） | 需心跳保活、断线重连 | | 适用场景 | 普通回调场景 | 高实时性、无固定公网IP场景 | ## 三、适用场景 推荐使用WebSocket长连接的核心场景： 1.  服务部署在内网，无公网可访问的回调URL 2.  业务对消息交互延迟有高实时性要求 3.  希望简化开发流程，无需处理消息加解密逻辑 ## 四、整体交互流程 1.  **连接建立**：开发者通过BotID+Secret发起WebSocket连接，发送`aibot_subscribe`完成订阅校验，保持长连接 2.  **进入会话**：用户首次进入机器人单聊，服务端推送`enter_chat`事件，开发者可通过`aibot_respond_welcome_msg`回复欢迎语 3.  **消息交互**：用户@机器人/单聊发消息，服务端推送`aibot_msg_callback`，开发者通过`aibot_respond_msg`回复，支持流式消息主动推送更新，`finish=true`结束流式消息 4.  **模板卡片交互**：用户点击模板卡片按钮，服务端推送事件，开发者通过`aibot_respond_update_msg`更新卡片内容 5.  **主动推送**：无用户消息触发时，通过`aibot_send_msg`向已交互会话主动推送消息 6.  **心跳保活**：开发者每30秒发送`ping`心跳请求，维持连接活跃 ## 五、长连接配置说明 ### 5.1 开启长连接API模式 在企业微信管理后台进入智能机器人配置页，开启「API模式」并选择「长连接」方式。 > 注意：API模式仅支持长连接/回调地址二选一，切换后原有模式会立即失效。 ### 5.2 获取接入凭证 开启长连接后获取以下专属凭证，Secret需妥善保管，与回调模式的Token/EncodingAESKey不通用： | 凭证 | 说明 | | :--- | :--- | | BotID | 智能机器人唯一标识，用于身份识别 | | Secret | 长连接专用密钥，用于身份校验 | ## 六、建立长连接 ### 6.1 WebSocket连接地址 ``` wss://openws.work.weixin.qq.com ``` ### 6.2 连接数量限制 1.  单个机器人同一时间仅支持1个有效长连接，新连接订阅成功会踢掉旧连接，旧连接会收到`disconnected_event`并被服务端断开 2.  高可用建议采用主备切换模式，禁止同时建立多连接 3.  订阅请求有频率保护，订阅成功后禁止反复发送，否则会触发系统限制 ### 6.3 连接建立流程 1.  向官方地址发起WebSocket连接 2.  握手成功后发送`aibot_subscribe`订阅请求（携带BotID+Secret） 3.  服务端校验凭证并返回结果 4.  校验成功，连接建立完成，开始接收回调 ### 6.4 订阅请求规范 #### 请求示例 ```json {    "cmd": "aibot_subscribe",    "headers": {"req_id": "REQUEST_ID"},    "body": {"bot_id": "BOTID", "secret": "SECRET"} } ``` #### 请求字段说明 | 字段 | 类型 | 必填 | 说明 | | :--- | :--- | :--- | :--- | | cmd | string | 是 | 固定值`aibot_subscribe` | | headers.req_id | string | 是 | 开发者自行生成，用于关联请求与响应 | | body.bot_id | string | 是 | 机器人BotID | | body.secret | string | 是 | 长连接专用Secret | #### 响应示例 ```json {    "headers": {"req_id": "REQUEST_ID"},    "errcode": 0,    "errmsg": "ok" } ``` #### 响应字段说明 | 字段 | 类型 | 说明 | | :--- | :--- | :--- | | headers.req_id | string | 透传请求的req_id | | errcode | int | 错误码，0为成功 | | errmsg | string | 错误信息，成功为ok | ## 七、接收消息回调 用户向机器人发消息时，服务端通过长连接推送`aibot_msg_callback`回调，各消息类型body结构与回调地址模式完全一致。 ### 7.1 消息推送格式（文本消息示例） ```json {    "cmd": "aibot_msg_callback",    "headers": {"req_id": "REQUEST_ID"},    "body": {        "msgid": "MSGID", "aibotid": "AIBOTID", "chatid": "CHATID",        "chattype": "group", "from": {"userid": "USERID"},        "msgtype": "text", "text": {"content": "@RobotA hello robot"}    } } ``` #### 核心字段说明 | 字段 | 类型 | 说明 | | :--- | :--- | :--- | | cmd | string | 固定值`aibot_msg_callback` | | headers.req_id | string | 请求唯一标识，回复时需透传 | | body.msgid | string | 回调唯一标识，用于事件排重 | | body.chatid | string | 会话ID，仅群聊返回 | | body.chattype | string | 会话类型：single(单聊)/group(群聊) | | body.from.userid | string | 消息发送者userid | | body.msgtype | string | 消息类型 | ### 7.2 支持的消息类型 | 消息类型 | msgtype | 说明 | | :--- | :--- | :--- | | 文本消息 | text | 用户发送的文本内容 | | 图片消息 | image | 用户发送的图片，仅支持单聊 | | 图文混排 | mixed | 用户发送的图文混排内容 | | 语音消息 | voice | 用户发送的语音（已转文本），仅支持单聊 | | 文件消息 | file | 用户发送的文件，仅支持单聊 | ### 7.3 多媒体资源解密 `image`/`file`类型会返回`url`和唯一`aeskey`用于解密资源，**每个url对应唯一aeskey**，与回调模式的统一EncodingAESKey不同。 #### 结构体示例 ```json // 图片资源 {"image": {"url": "URL", "aeskey": "AESKEY"}} // 文件资源 {"file": {"url": "URL", "aeskey": "AESKEY"}} ``` #### 字段说明 | 字段 | 类型 | 说明 | | :--- | :--- | :--- | | url | string | 资源下载地址，5分钟内有效 | | aeskey | string | 解密密钥，每个链接唯一 | #### 加密规则 - 加密方式：AES-256-CBC，数据采用PKCS#7填充至32字节倍数 - IV初始向量：取aeskey前16字节 ## 八、接收事件回调 用户与机器人发生交互时，服务端推送`aibot_event_callback`事件回调，除连接断开事件外，其余事件body结构与回调地址模式完全一致。 ### 8.1 事件推送格式（进入会话示例） ```json {    "cmd": "aibot_event_callback",    "headers": {"req_id": "REQUEST_ID"},    "body": {        "msgid": "MSGID", "create_time": 1700000000, "aibotid": "AIBOTID",        "from": {"userid": "USERID"}, "msgtype": "event",        "event": {"eventtype": "enter_chat"}    } } ``` #### 核心字段说明 | 字段 | 类型 | 说明 | | :--- | :--- | :--- | | cmd | string | 固定值`aibot_event_callback` | | headers.req_id | string | 请求唯一标识，回复时需透传 | | body.msgtype | string | 事件回调固定为`event` | | body.event.eventtype | string | 事件类型 | | body.create_time | int | 事件产生时间戳 | ### 8.2 支持的事件类型 | 事件类型 | eventtype | 说明 | | :--- | :--- | :--- | | 进入会话事件 | enter_chat | 用户当天首次进入机器人单聊会话 | | 模板卡片事件 | template_card_event | 用户点击模板卡片按钮 | | 用户反馈事件 | feedback_event | 用户对机器人回复进行反馈 | | 连接断开事件 | disconnected_event | 新连接建立，旧连接被断开时推送 | ### 8.3 连接断开事件格式示例 ```json {    "cmd": "aibot_event_callback",    "headers": {"req_id": "REQUEST_ID"},    "body": {        "msgid": "MSGID", "create_time": 1700000000, "aibotid": "AIBOTID",        "msgtype": "event", "event": {"eventtype": "disconnected_event"}    } } ``` ## 九、回复消息 收到消息/事件回调后，通过指定命令回复，部分回复有严格的时效/场景限制，必须透传回调中的`req_id`。 ### 9.1 回复欢迎语 - 适用场景：仅`enter_chat`进入会话事件 - 时效要求：收到事件后**5秒内**发送 - 固定命令：`aibot_respond_welcome_msg` #### 请求示例 ```json {    "cmd": "aibot_respond_welcome_msg",    "headers": {"req_id": "REQUEST_ID"},    "body": {        "msgtype": "text",        "text": {"content": "您好！我是智能助手，有什么可以帮您的吗？"}    } } ``` #### 响应示例 ```json {    "headers": {"req_id": "REQUEST_ID"},    "errcode": 0,    "errmsg": "ok" } ``` ### 9.2 回复普通消息 - 适用场景：`aibot_msg_callback`消息回调 - 固定命令：`aibot_respond_msg` - 版本要求：流式消息需企业微信客户端5.0.6及以上 - 频率限制：收到回调后，24小时内可向该会话回复30条，额度耗尽后消耗主动推送额度 #### 流式消息回复机制 1.  流式消息通过`stream.id`关联，首次使用新建消息，重复使用更新内容，`finish=true`结束消息 2.  时效要求：首次发送后**6分钟内**完成所有刷新并设置`finish=true`，否则自动结束 3.  长连接模式下流式刷新为**开发者主动推送**，同一次回调的所有流式回复需透传相同`req_id` #### 流式消息请求示例 ```json {    "cmd": "aibot_respond_msg",    "headers": {"req_id": "REQUEST_ID"},    "body": {        "msgtype": "stream",        "stream": {"id": "STREAMID", "finish": false, "content": "正在为您查询天气信息..."}    } } ``` #### 响应示例 ```json {    "headers": {"req_id": "REQUEST_ID"},    "errcode": 0,    "errmsg": "ok" } ``` ### 9.3 更新模板卡片 - 适用场景：仅`template_card_event`模板卡片点击事件 - 时效要求：收到事件后**5秒内**发送 - 固定命令：`aibot_respond_update_msg` #### 请求示例 ```json {    "cmd": "aibot_respond_update_msg",    "headers": {"req_id": "REQUEST_ID"},    "body": {        "response_type": "update_template_card",        "template_card": {            "card_type": "button_interaction",            "main_title": {"title": "xx系统告警", "desc": "服务器CPU使用率超过90%"},            "button_list": [                {"text": "确认中", "style": 1, "key": "confirm"},                {"text": "误报", "style": 2, "key": "false_alarm"}            ],            "task_id": "TASK_ID", "feedback": {"id": "FEEDBACKID"}        }    } } ``` #### 响应示例 ```json {    "headers": {"req_id": "REQUEST_ID"},    "errcode": 0,    "errmsg": "ok" } ``` ## 十、主动推送消息 ### 10.1 核心规则 - 固定命令：`aibot_send_msg`，无需依赖回调触发，**仅支持向用户已发消息的会话推送** - 频率限制：自然日单会话可主动推送10条；若用户近期发过消息，优先消耗该会话24小时30条回复额度 - 适用场景：定时提醒、异步任务通知、系统告警推送等 ### 10.2 请求格式（markdown示例） ```json {    "cmd": "aibot_send_msg",    "headers": {"req_id": "REQUEST_ID"},    "body": {        "chatid": "CHATID",        "msgtype": "markdown",        "markdown": {"content": "这是一条**主动推送**的消息"}    } } ``` #### 请求字段说明 | 字段 | 类型 | 必填 | 说明 | | :--- | :--- | :--- | :--- | | cmd | string | 是 | 固定值`aibot_send_msg` | | headers.req_id | string | 是 | 开发者自行生成，关联请求与响应 | | body.chatid | string | 是 | 会话ID：单聊填userid，群聊填回调获取的chatid | | body.msgtype | string | 是 | 支持template_card/markdown | | body.template_card | object | 否 | 模板卡片内容，msgtype为该值时必填 | | body.markdown | object | 否 | markdown内容，msgtype为该值时必填 | ### 10.3 响应格式 ```json {    "headers": {"req_id": "REQUEST_ID"},    "errcode": 0,    "errmsg": "ok" } ``` ### 10.4 支持的消息类型 | 消息类型 | msgtype | 说明 | | :--- | :--- | :--- | | 模板卡片 | template_card | 按模板卡片数据格式配置 | | Markdown | markdown | 按Markdown消息数据格式配置 | ## 十一、保持心跳 ### 11.1 心跳机制说明 1.  心跳间隔：建议每**30秒**发送一次`ping`请求 2.  超时规则：服务端长时间未收到心跳会主动断开连接 3.  容错要求：开发者需实现断线检测和自动重连机制 ### 11.2 心跳请求 ```json {    "cmd": "ping",    "headers": {"req_id": "REQUEST_ID"} } ``` ### 11.3 心跳响应 ```json {    "headers": {"req_id": "REQUEST_ID"},    "errcode": 0,    "errmsg": "ok" } ```
